0. 一分钟看懂

豆包输入法打字时用的「语音输入」，本质是客户端把麦克风音频发到字节的流式识别服务。它不需要登录、也没有对外公开 API，但它的凭据是按设备匿名下发的，所以我们可以自己复刻整条链路：

你的程序 ──①注册匿名设备──▶ log.snssdk.com 得到 device_id ──②用 device_id 换 key─▶ is.snssdk.com/settings 得到 asr_config.app_key ──③连 WebSocket────────▶ frontier-audio-ime-ws.doubao.com │ StartTask → StartSession │ TaskRequest（16k PCM / 20ms 一帧） │ FinishSession ◀──── ④识别结果（累积文本 + 逐字时间）──────────────────┘
能不能直接用？能，实测在 Linux 服务器上跑通了中文、英文、中英混说。 但它是未公开的内部接口：凭据按设备下发、随时可能变更或加风控，请只用于技术研究与自用，别拿去做对外产品（想产品化用火山引擎官方接口或本地开源模型）。

1.3 识别协议

一条 WebSocket 长连接，二进制 protobuf 帧，四个步骤：

连接 wss://frontier-audio-ime-ws.doubao.com/ocean/api/v1/ws?aid=685343&device_id=<did> 头部 User-Agent: com.bytedance.android.doubaoime/... ← 伪装成官方客户端 proto-version: v2 ← 关键！没有它就回 JSON 而不是 protobuf x-custom-keepalive: true ① StartTask { token=app_key, service=ASR } → TaskStarted ② StartSession { payload=会话参数 JSON } → SessionStarted ③ TaskRequest ×N { audio=20ms PCM, frame_state=1/3/9 } → 结果 JSON（累积文本） ④ FinishSession → SessionFinished

请求字段（实测得到的字段号）

字段号类型含义值
2stringtoken第 ② 步拿到的 asr_config.app_key
3stringservice_nameASR
5stringmethod_nameStartTask / StartSession / TaskRequest / FinishSession
6stringpayloadJSON 字符串（会话参数 / 每帧的时间戳）
7bytesaudio_data16k/单声道/PCM16，20 ms = 640 字节
8stringrequest_id自己生成的 UUID，用于对账
9varintframe_state首帧 1、中间 3、末帧 9

StartSession 的 payload

{
  "audio_info": { "channel": 1, "format": "raw", "sample_rate": 16000 },
  "enable_punctuation": true,
  "enable_speech_rejection": false,
  "extra": {
    "did": "<device_id>",
    "input_mode": "tool",
    "strong_ddc": true,            // 强纠错
    "use_twopass_retry": true,     // 二遍重试
    "enable_asr_twopass": true,    // 流式 + 整段两遍解码
    "enable_asr_threepass": true,  // 三遍
    "disable_user_words": false,   // 允许个人词库生效
    "cell_compress_rate": 8,
    "context": "<base64>"          // 可选：chat + ime_info + hotwords（热词偏置）
  }
}
音频格式：format 除了 raw（16k PCM16，最省事）也支持 speech_opus（官方客户端用的 Opus）。 用 raw 就不必自己实现 Opus 编码，实测同样能识别。

响应字段

字段号含义
2task_id
4事件名：TaskStarted / SessionStarted / SessionFinished / TaskFailed / SessionFailed
5状态码（见下表）
6状态文本
7结果 JSON（识别文本、时间、是否定稿）

结果 JSON（字段 7 的内容）

{
  "results": [{
    "text": "你好，这是语音识别测试",      // 本次发言的累积文本，最后一条即完整结果
    "start_time": 1.33, "end_time": 3.4,  // 秒，相对本次会话起点
    "confidence": 0.998,
    "is_interim": false,                  // false = 已定稿
    "is_vad_finished": true,              // VAD 判定这一句说完了
    "index": 0,
    "alternatives": [{ "text": "…", "words": [
        { "word": "你", "start_time": 0, "end_time": 0.34 }, …   // 逐字时间
    ]}]
  }]
}
两个实测坑： ① 短语气词会被反复改字（唉→哎→唉），三条消息 start_time 完全相同、只有 end_time 在涨——判断"新的一段"必须看起点，不能只看文本； ② alternatives[].words[].end_time 偏大（带前瞻窗口），做字幕要用"下一句的首字时间 / 整段 end_time"校正。

1.5 语言能力（实测）

输入结果结论
普通话「你好，这是微信语音接口测试，今天阳光很好。」支持
英语（JFK 演讲）「And so my fellow Americans, ask not what your country can do for you, ask what you can do for your country.」支持（标点大小写都对）
中文一句 + 英语一句（同一会话）两句各自按语言正确输出中英混输
日语「こんにちは」「国内计划。」不支持
日语「私は日本語を勉強しています」「马达西」+「我倒希望你哄我。」不支持（声学层听到了，但语言模型只有中文）

原因是这个模型是 zh + en 双语（即官方宣传的"中英混输"），客户端创建识别句柄时写死的是 speech_opus + zh； 协议里没有 language 字段，所以没有"切语种"的开关。要用日语只能换官方多语种接口或在本地跑开源日语模型。

1.6 豆包的离线识别是怎么做的

这是本轮最有价值的发现。结论先给：离线识别 = 字节自研端侧推理引擎 Flute + 联网下载的模型包， 而且 Windows 0.9.2.7 里还没有这套东西（Android / macOS 有）。

层证据Windows 0.9.2.7macOS 1.0.2Android 1.5.1
端侧推理引擎 Flute flute/engine/engine.cc、flute_c_api.cc、flute/framework/*、 flute/base/filesystem_mmap/filesystem_packed_mmap.cc（打包 mmap 模型容器） 无主程序内libaudioeffect.so
ASR 模型结构 flute/module/asr/ntp_cif/{encoder_actor,cif_calculator,beam_searcher,decoder_context/prompt_processor}、 feature/{mel_bank,panther,subband}_feature_extractor、module/vad/v4、module/signal/aec 无有有
SAMI 的本地 worker speech_v2/asr/offline/{asr_off_singleton,asr_off_worker}.cpp、capi/flute/asr/flute_asr.cpp 只有 online/*有有
模型下载管理 应用侧 OimeOfflineModel 模块：ASROfflineModel{Manager,FileStore,PathResolver,MetaInfoService,Manifest}、 通知 start/pause/resume/retry/requestDelete/updateOfflineModelState、 日志 ASR offline model path:、缺模型弹窗 ASROfflineModelUnavailablePromptWindowController 无有（APK 内未打包模型）

模型长什么样

macOS 主程序里写死了模型的张量文件名（93 个 .bin/.dat/json），可以直接读出结构 —— 是 PANTHER Conformer 编码器 + LLM 风格解码器，CIF（连续积分激发）机制，int8 量化：

s/panther_conformer_*                     编码器
s/panther_decoder_L*                      解码器
s/panther_l0_{qkv_pre_rope,mha_raw,ffn1_gemm1,ffn2_swiglu,rmsnorm1,rmsnorm2,conv_out}.bin
up_proj.bin / down_proj.bin / v_proj.bin / swiglu.bin / o_proj ...   权重张量
*_shape.dat / input_shape.dat / config.json / token_config.json / llm_params.json

算力后端是 CPU int8（源码里有 PackBS8 format: 4x4 tiled layout matching CPU prepacked weights） 加 GPU kernel（macOS 用 Metal，源码里带 device const char* 的着色器）。体量对得上"离线模型包约 150 MB"的说法。

在线 / 离线怎么协同（SAMI 里的融合策略）

  • PutOnlineCacheAudioToOffline：把在线期间缓存的音频交给整段识别重跑
  • [online vs offline] words num: [%d vs %d]：两份结果对比择优
  • 触发条件：asr has no network, switch to offline、asr has no result, switch to offline、recv interval time
  • 时间参数：finish_wait_offline_time / offline_wait_online_time / max_wait_switch_offline_time
  • 应用侧：openASRPanel canceled: network disconnected, offlineModelStatus=、Skip smart text enable prompt: reason=offline_result
为什么拿不过来用： ① 模型是私有逐张量格式，引擎里写死了张量名，版本一变就对不上； ② Flute 静态编进客户端，没有任何公开 API； ③ 模型包要从字节服务器鉴权下载。
但架构可以照抄，落地就用开源等价物（见 第 5 节）。

2. 凭据从哪来（为什么不用登录）

豆包输入法没有任何账号体系参与语音识别，身份是「应用身份 + 设备身份」：

① POST https://log.snssdk.com/service/2/device_register/ body: {magic_tag:"ss_app_log", header:{aid:685343, app_name:"oime", cdid/openudid/clientudid, …}} resp: {device_id, install_id, device_token} ← 匿名注册一台设备（头条系通用接口） ② POST https://is.snssdk.com/service/settings/v3/?device_id=<did>&cdid=<cdid> header: x-ss-stub = md5("body=null").upper() resp: data.settings.asr_config.app_key = "RTIHIRzbwS" ← ASR 用的 token，按设备下发 应用级 aid（编译进客户端）+ 设备级 app_key → 服务端据此计量/风控，不需要用户账号
要素值 / 说明
aid685343（取自 ImeService.exe）
User-Agentcom.bytedance.android.doubaoime/100102018 (Linux; U; Android 16; en_US; Pixel 7 Pro; Build/BP2A.250605.031.A2)
app_key按设备/时间下发（同一设备多次调用会拿到稳定的值，换设备就变），建议缓存 12 小时
为什么不需要登录身份建立在"应用 + 设备"上；这也是头条系 App 的通用做法（安装即匿名注册）
你的程序里不要暴露 app_key 给前端（它是设备级凭据），网页端一律走服务端中转。

3. 自己写客户端

下面三份代码都是完整可运行的单文件客户端：自己注册设备、拿 app_key、跑完一次识别并打印文本。 复制走改一改就能用（asr_min.py / asr_min.js / asr_min.go 也可直接下载）。

Python

pip install websockets
python asr_min.py test.wav        # 输出：你好，这是微信语音接口测试，今天阳光很好。
@@PY@@

Node.js

npm i ws
node asr_min.js test.wav
为什么不用 Node 自带的全局 WebSocket：上游靠 proto-version: v2 这个握手头来选择二进制 protobuf 协议， 没有它就回 JSON；而全局 WebSocket 和浏览器一样无法设置自定义请求头，所以这里用 ws 包。
@@JS@@

Go

cd examples && go mod tidy && go run asr_min.go test.wav
@@GO@@
三份代码的共同骨架（照这个顺序写就不会错）： ① 注册设备 → ② 换 app_key → ③ 连 WS（带 proto-version: v2）→ ④ StartTask → ⑤ StartSession → ⑥ 循环发 20ms 帧（首帧 1 / 中间 3 / 末帧 9）→ ⑦ FinishSession → ⑧ 读到最后一条累积文本。

4. 集成到你的项目

4.1 网页端为什么要中转

上游需要 3 个无法从浏览器发出的东西：自定义 WS 请求头（proto-version 等）、 设备级 app_key（不能下发到前端）、以及 HTTP 注册请求。所以浏览器方案必须是：

浏览器 ──(16k PCM / WebSocket)──▶ 你的服务端 ──(protobuf / WebSocket)──▶ 字节识别服务 ↑ 录音、去噪、重采样、实时上屏 ↑ 管凭据、帧序号、重试、降级

本 Demo 就是这么做的：前端只管录音和显示，服务端负责凭据、分帧、重试、降级、纠正词典。

4.2 本 Demo 的接口（可直接对接）

本项目的线上演示：doubao.hsfp.cn （代码就是本仓库）。下面示例里的 <你的域名> 换成你自己的部署地址即可。

接口说明
GET /录音页面（前端可直接抄 /static/index.html + /static/worklet.js）
WS /ws?engine=auto|cloud|local转写会话；auto = 云端优先，失败自动降级本地引擎
GET /health状态、设备凭据是否就绪、并发上限、纠正/热词数量
GET /api/lexicon纠正词典 + 热词
POST /api/corrections{"wrong":"识别错的","right":"用户改成的"}：记住并影响后续识别
POST|DELETE /api/hotwords手加热词 / 删除

{"type":"final","engine":"cloud","lines":[…],"text":"…","error":null}
{"type":"error","message":"…"}

{"text":"你好。","start":0.0,"end":1.3,"ts":1792130303000,"final":true,
 "orig":"你号。","fixes":[["你号。","你好。"]]}   // orig/fixes 只在命中本地纠正时出现

最小前端调用示例（浏览器）

// 采集侧：AudioWorklet 把任意采样率转成 16k PCM16（完整实现在 static/worklet.js）
const ws = new WebSocket(`wss://<你的域名>/ws?engine=auto`);
ws.binaryType = "arraybuffer";

const ctx = new AudioContext({ sampleRate: 16000 });
await ctx.audioWorklet.addModule("/static/worklet.js");

// 适合「把一批录音文件转成文字」：连本 Demo 的 /ws，喂 PCM，收最终文本
import fs from "node:fs";
import WebSocket from "ws";

async function transcribeFile(path) {
  const pcm = readWav16kMono(path);                       // 见 examples/asr_min.js 的 readWav
  const ws = new WebSocket("wss://<你的域名>/ws?engine=auto");
  return new Promise((resolve, reject) => {
    let done = null;
    ws.on("open", async () => {
      for (let i = 0; i < pcm.length; i += 640) {
        ws.send(pcm.subarray(i, i + 640));
        await new Promise((r) => setTimeout(r, 20));      // 按实时速度喂（也可更快）
      }
      ws.send(JSON.stringify({ type: "stop" }));
    });
    ws.on("message", (raw) => {
      const msg = JSON.parse(raw);
      if (msg.type === "final") { done = msg; resolve(msg.text); ws.close(); }
      if (msg.type === "error") reject(new Error(msg.message));
    });
    ws.on("close", () => { if (!done) reject(new Error("连接提前关闭")); });
  });
}

4.3 生产环境注意事项

点建议
凭据缓存device_id + app_key 落盘复用（600 权限），别每次请求都重新注册
重试50700000 是随机抖动（约 1/5），整段重试 3~4 次；40200011 不要重试（配额满）
并发所有客户端共享同一个 app_key 的配额，服务端做信号量（本 Demo 默认 3 路）
帧节奏按实时速度喂即可（20 ms/帧 = 32 KB/s）；一次性灌太快容易触发异常
末帧实时流不知道哪帧是最后一帧 → 压一帧，收尾时把压着的这帧标 9 再发 FinishSession
安全不要在前端暴露 app_key；服务端加鉴权（本 Demo 用 API key / 访问控制即可）
合规这是未公开的内部接口，接口可能变更、风控可能封禁；正式产品请用官方接口（见下节）

6. 常见问题

Q：为什么我自己连不上，一直 50700000？

上游随机抖动（实测约 1/5），重试整段即可。如果重试也一直失败，可能是接口变了或被风控，换新设备试试、或改用本地引擎。

Q：直接用 whisper-1 模型名行不行？

不行，这不是 OpenAI 接口。字段 5 是固定的方法名，音频字段是裸 PCM/Opus，不解析 multipart。

Q：能不能不注册设备、硬编码一个 app_key？

不建议：app_key 按设备下发且会轮换，硬编码很快就失效；而且那属于拿别人的凭据。

Q：识别结果能拿到逐字时间吗？

能，在 results[].alternatives[].words[] 里（注意 end_time 偏大，需要按 1.3 的坑校正）。

Q：能做成 OpenAI 兼容的 /v1/audio/transcriptions 吗？

能，服务端包一层即可：接收 multipart → 转 16k PCM → 走本节协议 → 返回 {"text": ...}。 本 Demo 目前只提供了 WebSocket 接口，需要 HTTP 版可以照着 4.2 的协议自己加。

本文所有结论均来自对公开安装包的分析与实测（2026-10-16）。项目与腾讯、字节跳动、豆包均无隶属关系； 接口为未公开的内部接口，仅供技术研究，请勿用于对外商业产品。相关代码示例按 MIT 使用。
